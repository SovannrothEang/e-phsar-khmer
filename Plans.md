### Plan: Web dark mode — every surface and label follows the theme (2026-11-10)

**Purpose**: Dark mode was retrofitted at the shell level: the provider, `.dark` tokens, body `bg-background text-foreground` and most `components/ui/*` primitives are correct, but feature components still carry light-mock values. ### Plan: Report-threshold account suspension, the delete/inactive split, and the first runtime setting (2026-11-08)

**Purpose**: Moderation today is one decision at a time: approving a single report suspends the account and permanently burns every phone number it holds (a one-way door with no unban endpoint, no reason column, and no appeal surface), while a report that nobody is looking at counts for nothing. This plan makes approved reports accumulate into a triage signal — at a configurable threshold, staff are notified in-app and **nothing happens automatically** — and makes a suspension explainable and reversible: a stored reason, every session ended, a login attempt that returns `403 { code: 'ACCOUNT_SUSPENDED', reason, support }` so the client can show a dialog with the contact channels, and manual reinstatement. It also splits the two listing states that are currently confused: `delete` becomes permanent (a marker, no row removal, no restore by anyone) and `inactive` stays the staff-only, reversible hide. The threshold is the first value that must change without a redeploy, so it lands in a generic DB-backed settings store, not an env var.

### Plan: Keep E2E, stop the "Sent before this device was set up" wall (2026-10-26)

OTP cannot be proven without a real SMS. _Security/Skeptic_: `EXPO_PUBLIC_*` is public by definition — never move a secret there; keep the EAS keystore out of the repo; reject runtime URL switching, cleartext and a LAN-pointed production APK; a debug-key-signed APK cannot be updated by an EAS-signed one, so do not mix the two for the same testers.

(3) The repo is a pnpm workspace; EAS monorepo installs are unverified here — a failed install is recorded, not worked around by copying files. (4) The deployed backend may be stale: `/listings/nearby` 404s and the size filters 400 until a deploy; Task 0.1 decides whether to deploy first or accept the degraded surface. (5) Production OTP depends on real PlasGate SMS and Redis; signed-in phone verification is `unknown` unless a real code is sent. (6) The working tree carries uncommitted product-spec work; EAS uploads the working tree, so 2.1 must freeze and record the exact tree (or land that branch first). (7) R8/minify release-only failures can appear; fix them rather than disabling minify silently. (8) No `expo-updates`: every JS change needs a new build and a bumped versionCode. (9) The local `android/` tree is incomplete; never use it for a fallback without `expo prebuild --clean` and the Tencent mirror restored. (10) A local debug-key APK and an EAS-key APK cannot update over each other; testers must uninstall once if the fallback ships first.
